LongAdderAnalyzer реализует WordAnalyzer и использует ConcurrentHashMap<String,LongAdder>. Здесь значением карты является не неизменяемый Integer, а изменяемый потокобезопасный счётчик LongAdder.

Общая карта создаётся перед запуском заданий. Работники читают назначенные файлы и для каждого слова выполняют counts.computeIfAbsent(word, key -> new LongAdder()).increment().

computeIfAbsent возвращает существующий счётчик либо атомарно связывает отсутствующий ключ с новым LongAdder. Лямбда key -> new LongAdder() задаёт создание счётчика. После получения ссылки вызывается increment, который потокобезопасно увеличивает значение.

Нельзя называть всё выражение одной атомарной операцией ConcurrentHashMap: получение счётчика и его увеличение — разные действия. Здесь сочетание корректно, потому что счётчики не удаляются и не заменяются, а сам increment допускает конкурентные вызовы.

При конкуренции LongAdder может распределять увеличения между внутренними ячейками, снижая борьбу за одно значение. Это может повысить пропускную способность ценой памяти; выигрыш не гарантирован для любых данных и числа потоков.

AnalysisSupport.run дожидается всех работников. Затем создаётся обычный HashMap<String,Long>, и для каждого счётчика вызывается sum. Во время продолжающихся обновлений sum не является атомарным снимком, но после завершения всех задач даёт точный итог. Готовый словарь возвращается вызывающему коду.
