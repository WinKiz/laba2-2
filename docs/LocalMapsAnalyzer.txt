LocalMapsAnalyzer реализует подсчёт с отдельными словарями работников. Здесь нет одной общей изменяемой карты на стадии чтения файлов.

AnalysisSupport.run распределяет файлы между заданиями. HashMap<String,Integer> создаётся внутри лямбды задания, поэтому каждое задание получает свой новый словарь. Работник читает свои файлы и увеличивает свои счётчики через merge с Math::addExact.

Обычный HashMap здесь допустим: каждый словарь изменяет только его работник. Совпадение ключей в разных словарях не создаёт гонки, потому что это разные объекты. Поэтому защищать каждое локальное увеличение не нужно.

Задание возвращает свою карту. Метод run ждёт завершения всех заданий и возвращает List<Map<String,Integer>>. Ожидание нужно, чтобы главный поток объединял уже готовые результаты.

После этого вызывающий поток создаёт один итоговый HashMap<String,Long>. Для каждой локальной пары результат обновляется через result.merge(word, count.longValue(), Math::addExact). Здесь прибавляется весь локальный счётчик, а не единица. Объединение выполняется последовательно, поэтому общий итоговый HashMap тоже не требует защиты от одновременных изменений.

Вернувшийся словарь содержит сумму по всем файлам. Преимущество — отсутствие конкуренции за карту во время подсчёта. Расходы — несколько словарей в памяти и отдельное слияние, которое входит во время обработки. Поэтому этот способ не обязан быть самым быстрым при любом размере задачи.
